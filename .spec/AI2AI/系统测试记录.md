## 6. 缺陷与风险清单

### BUG-001【中危·已确认】管理员删除用户接口响应逻辑反转

- **位置**：[controller/user.go](file:///e:/97_OneAI/one-api/controller/user.go#L504-L511) `DeleteUser`
- **现象**：`DELETE /api/user/:id` 删除**成功**时（err==nil）函数直接结束，**响应体为空**（无任何 JSON）；删除**失败**时（err!=nil）反而返回 `{"success":true}`。
- **根因**：错误分支与成功分支写反，且成功路径缺少 `c.JSON`：

```go
err = model.DeleteUserById(id)
if err != nil {
    c.JSON(http.StatusOK, gin.H{
        "success": true,   // ← 应为 false + err.Error()
        "message": "",
    })
    return
}
// ← 此处缺少成功响应 c.JSON(...success: true...)
```

- **对比**：同文件 `DeleteSelf`（L525-L537）实现正确（失败 success:false + err，成功 success:true）。
- **影响**：前端管理页删除用户后收不到标准响应体，无法正确提示结果；删除失败时误报成功。数据层删除本身正常（本次测试用户均已实际删除）。
- **修复建议**：将 if 块改为 `success:false, message:err.Error()`，并在 if 之后补 `c.JSON(http.StatusOK, gin.H{"success":true,"message":""})`。

### OBS-02【低危·加固建议】注册接口不校验两次密码一致性

- **位置**：[controller/user.go](file:///e:/97_OneAI/one-api/controller/user.go#L113-L172) `Register`
- **现象**：后端不接收/校验 `password2`，两次密码一致性仅由前端 RegisterForm 拦截；直接调用 API 时以第一次输入的密码注册成功。
- **评估**：上游 one-api 原版行为，无安全漏洞（用户本人对自己输入的密码负责），但体验上绕过了前端保护。建议后端增加 password2 一致性校验或在文档中明确该约定。

### OBS-03【低危·加固建议】用户管理接口按 username 定位、空 username 时条件退化

- **位置**：[controller/user.go](file:///e:/97_OneAI/one-api/controller/user.go#L591-L619) `ManageUser` / `ManageRequest{Username, Action}`
- **现象**：`/api/user/manage` 用 `username` 查用户（非 id）；当 username 传空串时，Gorm 结构体零值条件被忽略，`First` 命中表中第一个用户（id=1 root）。实测空 body 调 disable 返回"无法禁用超级管理员用户"，证明定位到了 root。
- **评估**：前端始终携带 username，UI 路径不可利用；且 root 有超管保护兜底，无实际越权后果。但 API 契约脆弱，建议：username 为空时直接返回参数错误，或改用 id 定位。

### OBS-04【低危·加固建议】会话 Cookie 安全标志未显式设置

- **位置**：[main.go](file:///e:/97_OneAI/one-api/main.go#L111) `store := cookie.NewStore([]byte(config.SessionSecret))`
- **现象**：实测登录响应 `Set-Cookie: session=...; Path=/; Expires=...; Max-Age=2592000` 未显式携带 HttpOnly / Secure / SameSite 属性。
- **评估**：生产环境（HTTPS 部署）建议显式配置 `store.Options = &sessions.Options{Path:"/", HttpOnly:true, Secure:true, SameSite:http.SameSiteLaxMode, MaxAge:...}`，降低 XSS 窃取会话与 CSRF 风险。本地 HTTP 开发环境不受影响。
