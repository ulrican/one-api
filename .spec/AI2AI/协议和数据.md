### 1.8 扩展表：`model_ratio_locks`（Task4-3 模型倍率手动锁定，已实施）

> 倍率自动重算流程的"跳过名单"，一模型一行；**不改动 option 表既有 ModelRatio/CompletionRatio/GroupRatio 三 key**，锁定行只控制自动流程是否覆盖。`model/model_ratio_lock.go`，AutoMigrate 注册（实测 2026-09-18）。

| 列 | 类型 | 说明 |
| :--- | :--- | :--- |
| model_id | varchar(128) PK | 与 `ratio.ModelRatio` 的 key 一致（七牛 id 含 `/`，如 `deepseek/deepseek-v3.1`） |
| model_ratio | decimal(12,6) | 锁定时的输入倍率快照（0 = 锁时现值也无，允许） |
| completion_ratio | decimal(12,6) | 锁定时的输出倍率快照 |
| locked_by | int（DB 实际 bigint） | 操作人 user_id |
| locked_at | bigint | 锁定时间戳（秒） |
| note | varchar(256) | 备注（可空） |

- `UpsertModelRatioLock`：`ON CONFLICT(model_id)` 全列更新（重复锁定=更新，幂等，locked_by/locked_at 以最新操作者为准）；`DeleteModelRatioLock` 删行解锁（未命中不报错，倍率现值保留，下次重算覆盖）；`GetAllModelRatioLocks`（locked_at DESC）/`GetModelRatioLockMap`（重算热路径用 map）/`IsModelRatioLocked`。
- 写锁定的 Service 入口 `model.LockModelRatio(modelId, *float64, *float64, lockedBy, note)`（`model/ratio_compute.go`）：先 upsert 锁定行（指针项传 nil = 快照现值，仅加锁不改值），再把非 nil 的倍率经 `ratio.Apply*Updates` + `UpdateOption` 立即落 option 表热生效。

> 套餐 = 付费后开通指定用户组（vip/svip 等，组须已存在于 GroupRatio）的模版，复用在线支付链路；回调事务内切换 users.group 并写有效实例，到期后 GetUserGroup 惰性降回 default。**users 表不改结构（沿用 group 列）、relay/ 零改动**。`model/package.go`，AutoMigrate 注册；orders 加 package_id 列（见 1.2）。

| price | decimal(10,2) | 售价（元） |

| created_at / updated_at | bigint | 时间戳（秒） |

**user_packages（用户套餐实例，到期判定数据源）**：

| 列 | 类型 | 说明 |
| :--- | :--- | :--- |
| id | int PK | 自增 |
| user_id | int index | 用户 |
| package_id | int index | 来源套餐 |
| group_name | varchar(32) index | 开通组 |
| order_trade_no | varchar(64) | 开通订单号 |
| start_at | bigint | 开通时间 |
| expire_at | bigint | 到期时间（0=永久） |
| status | int index | 1 有效 / 0 失效（续费或降级时旧实例置 0） |
| created_at | bigint | 时间戳（秒） |

**开通链路（FinishOrderTrade 套餐分支，全部同一事务）**：
1. 锁订单 + 金额强校验（与充值单一致）；
2. 事务内 SELECT users.id 做存在性校验（不依赖 RowsAffected）；
3. 查套餐（不存在则回滚）→ 失效该用户同组旧有效实例（DeactivateUserPackages）→ 写新 user_packages（expire=now+duration_days×86400）→ UPDATE users SET group=套餐组 → 写充值日志（内容「购买套餐「X」」）；
4. 回调成功后清 `user_quota:<id>` + `user_group:<id>` 缓存。幂等沿用订单状态：重复回调 credited=false 不重复开通。

**到期惰性降级（model.GetUserGroup 内 tryDowngradeExpiredPackage）**：
- 用户组为空/default：不处理；
- 非 default 组且 user_packages **无任何历史记录**：管理员手工分配，不动；
- 有历史记录但**无有效实例**（status=1 且 expire_at=0 或 >now）：事务内置 users.group='default' + 失效旧实例 + 删 Redis 组缓存（降级写操作仅触发一次）；
- 该检查仅在 Redis 未命中回源 DB 时发生（多一次索引 COUNT），失败不阻断鉴权（按当前组返回）。

## 2. 前后端协议

### 2.1 前端调用约定

- 管控面 REST：`/api/...`（axios 封装见 `web/default/src/helpers/api.js`，登录态由 cookie/session 维持）
- 数据面网关：`/v1/chat/completions` 等 OpenAI 兼容协议（`Authorization: Bearer sk-xxxx`）
- 统一响应：`{ success: bool, message: string, data: any }`
- 系统状态：`GET /api/status`（system_name、logo、version、footer_html、chat_link、各登录开关等，前端缓存于 localStorage）
- 首页内容：`GET /api/home_page_content`（markdown 或 https 外链 iframe）；公告：`GET /api/notice`

### 2.2 Task01 新增协议

**无。** 新版落地页（阶段 3 起为根路径 `/`，旧 `/landing` 重定向至 `/`）为纯静态营销页：
- 不新增后端接口；品牌名/Logo 复用 localStorage 中 `/api/status` 的缓存（`getSystemName()`/`getLogo()`）
- 终端示例 Base URL 由前端 `window.location.origin + '/v1'` 动态生成
- 页面按钮全部跳转**既有前端路由**：
  - 导航"控制台 / 登录"：未登录 → `/login`；已登录 → `/dashboard`
  - Hero"免费获取 API Key"：未登录 → `/register`；已登录 → `/application`
  - "在线体验模型" → `/experience`（2026-10-12 起，原"体验在线 WebChat"→/chat→/playground 链路已随对话功能下线调整）
  - 模型卡"调用文档" → 同"免费获取 API Key"逻辑
  - Logo → `/`（现有首页）

### 2.3 鉴权约定（前端）

- 登录态：`UserContext`（`userState.user`），持久化于 `localStorage.user`
- 路由守卫：`components/PrivateRoute`（未登录跳登录页）
