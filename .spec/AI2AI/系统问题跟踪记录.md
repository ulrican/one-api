## 二、核心机制详解：充值金额 → 到账额度 → 模型倍率 → 费用计算（重点）

### 2.1 全链路总览

```
【充值侧】                                      【消费侧】
支付 ¥10                                        用户调用 API（N 输入 tokens / M 输出 tokens）
  │                                               │
  ▼                                               ▼
quota = ⌊10 ÷ 7.3 × 500000⌋ = 684,931          扣费 = (N×ModelRatio + M×ModelRatio×CompletionRatio)
  │（PayNotify 事务 + 行锁 + 幂等 + 原子加）        × GroupRatio × 0.002 × 500000 ÷ 1000
  ▼                                               │
用户 quota +684,931  ────────────────────────→  余额扣减，日志记录
```

两侧通过同一基准闭环：**quota 是唯一计费货币，1 quota 单位无关金额；$1 额度 ≡ 500,000 quota ≡ 充值 ¥7.3**。

### 2.2 充值金额 → 到账额度（Quota）

**公式**（[controller/pay.go:79](../../controller/pay.go)）：

```
到账 quota = ⌊ 充值金额(元) ÷ PayPrice × QuotaPerUnit ⌋     ← int64 截断（向下取整）
```

| 参数 | 含义 | 当前值 | 配置入口 |
|---|---|---|---|
| PayPrice | 充值价格：买 1 美元额度所需人民币 | **7.3** | 运营设置 → 在线支付设置 |
| QuotaPerUnit | 1 美元额度 = 多少 quota | **500,000** | 系统常量（$0.002/1K 基准的反推），勿改 |

**示例（充值页 ¥10 档，与页面显示「到账约 684.9k」一致）**：

```
10 ÷ 7.3 × 500000 = 684,931.50  →  ⌊截断⌋ = 684,931 quota
折合美元额度：684931 ÷ 500000 ≈ $1.37
```

- 前端预览与后端同公式同截断（`Math.floor`，[TopUp/index.js:284-287](../../web/default/src/pages/TopUp/index.js)）
- **显示格式**由系统设置「以货币显示额度」（display_in_currency）决定：开启 → `$1.37`（quota÷500000）；关闭 → `684.9k`（renderNumber 缩写）。当前为后者
- **到账动作**（PayNotify，[controller/pay.go:151-191](../../controller/pay.go)）：易支付回调 → MD5 验签 + pid 归属校验 + 金额一致性校验 → 事务内 `FOR UPDATE` 行锁查订单 → `Status==Paid` 幂等防重 → `UpdateColumn("quota", gorm.Expr("quota + ?"))` 原子加 → `cleanUserCache` 刷 Redis。开通前需把 ServerAddress 配为公网 HTTPS 域名，否则回调不可达
- 防线提醒：`RedisDel` 等调用必须先判 `common.RedisEnabled`（F1 踩过）

### 2.3 模型倍率体系（价格的定义源）

价格页显示的人民币价**不是直接配置的**，由三层倍率换算：

```
输入价($/1K) = ModelRatio × 0.002            ← 基准：1 倍率 ≡ $0.002/1K ≡ ¥0.014/1K
输出价($/1K) = 输入价 × CompletionRatio       ← 输出相对输入的倍数
价格页人民币标价 = 美元价 × 7                 ← USD2RMB=7.0 硬编码（relay/billing/ratio/model.go:12）
```

**ModelRatio / CompletionRatio 取值优先级**（[relay/billing/ratio/model.go:686-710](../../relay/billing/ratio/model.go)）：

1. DB options 表 `ModelRatio` / `CompletionRatio`（后台 → 运营设置 → 倍率设置 JSON，保存即生效）
2. 内置默认表（[model.go:27](../../relay/billing/ratio/model.go) / [:624](../../relay/billing/ratio/model.go)，按各家官方价目折算，随代码版本走）
3. 都查不到 → **兜底 30**（=$0.06/1K，防漏配按最贵收）

**当前实例实际值**（09-14 实测 `/api/pricing`）：

| 模型 | ModelRatio | 输入价($/1K) | 补全倍率 | 输出价($/1K) | 来源 |
|---|---|---|---|---|---|
| deepseek-chat | 0.07 | $0.00014 | 2 | $0.00028 | 内置表（DeepSeek 官方价 ¥1/¥2 每 M） |
| deepseek-reasoner | 0.275 | $0.00055 | ≈3.98 | $0.00219 | 内置表（R1 官方价） |
| deepseek-flash | **30（兜底）** | $0.06 | — | — | ⚠️ RISK-001 未配倍率 |
| deepseek-v4-pro | **30（兜底）** | $0.06 | — | — | ⚠️ RISK-001 未配倍率 |

GroupRatio（分组倍率）：default=1.0；价格页展示时**不乘**分组倍率，实际计费才乘。

**价格页模型清单**来源：abilities 表（启用渠道暴露的模型并集），Redis 缓存 60 秒；价格接口 `/api/pricing` 为公开接口（无需鉴权）。

### 2.4 消费费用计算（扣费公式）

Relay 链路计费（数据面，仅内存/Redis 操作）：

```
本次扣费 quota = ( 输入tokens × ModelRatio + 输出tokens × ModelRatio × CompletionRatio )
                × GroupRatio × 0.002 × 500000 ÷ 1000
```

即每 1K tokens：`输入 70 quota/1K`（chat，ratio=0.07 时）、`输出 140 quota/1K`（补全倍率 2）。

**全链路数字闭环示例（¥10 充值 → deepseek-chat 消费）**：

```
充值 ¥10 → 到账 684,931 quota（=$1.37）
deepseek-chat 输入：684931 ÷ 70 ≈ 978 万 tokens 可跑（仅输入口径）
若输入输出各半：÷105/1K ≈ 652 万 tokens
```

### 2.5 已知换算口径问题（关联 RISK 项）

| 问题 | 说明 | 影响 | 处置建议 |
|---|---|---|---|
| 汇率双轨 | 价格页标价按 7.0，充值成本按 7.3 | 用户视角"¥10 买 $1.37"与价格页标价差 4% | 统一两处（改 `USD2RMB` 常量或价格页改读 PayPrice） |
| 兜底 30 | 未配倍率的自定义模型按 $0.06/1K 计费 | deepseek-flash / v4-pro 被按最贵收，用户投诉风险 | 后台倍率设置 JSON 补两条，或进 adaptor `constants.go` |
| int64 截断 | 充值 quota 向下取整 | 单次最多差 1 quota，可忽略 | 保持现状（前后端已一致） |

## 三、已修复问题详情

### ISS-001 支付开关保存后被翻转（BUG-002）

- **根因**：前端所有 `*Enabled` 复选框为"勾选即保存"设计（`handleInputChange` → `updateOption` 按当前值取反发出 PUT）；再点「保存支付设置」时 `submitConfig('pay')` 检测到 `originInputs ≠ inputs` 二次提交，`updateOption` 对 `*Enabled` 键**再次取反** → 刚开的开关被关回
- **修复**（[OperationSetting.js](../../web/default/src/components/OperationSetting.js)）：`submitConfig('pay')` 移除 PayEnabled 重复提交（复选框即时生效）；同款缺陷 RankingEnabled 一并修复并删除失效"保存"按钮
- **验证**：勾选即时 PUT true → 点保存不再发翻转请求 → 刷新保持开启 → `/api/user/pay/config` enabled=true
- **教训**：即时生效型开关与"整块保存"逻辑混用时，必须防止同一键在两条路径重复提交取反

### ISS-003 图标 7 天强缓存

- **根因**：后端对静态资源下发 `Cache-Control: max-age=604800`；页头 `<img src="/logo.png">` 在缓存期内不回源。`/api/status` 无长缓存 → 名称先变、图标后变（用户感知"图标没变，名称变了"）
- **修复**：[utils.js](../../web/default/src/helpers/utils.js) 新增 `LOGO_VERSION`，logo 请求改 `/logo.png?v=20260914`（新缓存键强制回源）；[index.html](../../web/default/src/public/index.html) 两处 favicon 同步加 `?v=`
- **约定（重要）**：今后更换 logo.png / favicon.ico 必须同步递增 `LOGO_VERSION` 与 index.html 的 `?v=`，否则用户浏览器 7 天内不更新
- **走查方法教训**：验证图标必须查页面 `<img>` 的实际 src 与渲染结果，不能只用 `?cb=` 绕缓存验证服务器文件

### ISS-004 落地页图标双框模糊

- **根因**：落地页把 512px 完整图标（自带圆角 tile+光晕）塞进 `.tl-logo-mark`（渐变描边）+ `.tl-logo-mark-inner`（深色内衬）装饰结构，压到 22px → 叠加成模糊块；控制台是裸 img 30px/圆角 8px
- **修复**：[Landing/index.js](../../web/default/src/pages/Landing/index.js) 图标改裸 `<img class="tl-logo-img">`（保留加载失败时 ⚡ 兜底）；[landing.css](../../web/default/src/pages/Landing/landing.css) 新增 `.tl-logo-img{height:30px;width:auto;border-radius:8px}` 与 `.app-brand-logo` 对齐，原 `.tl-logo-mark-inner img` 规则删除

### ISS-007（部分）落地页倍率卡 Infinity 边界

- **根因**：候选模型无匹配时 `Math.min(...[])` 返回 `Infinity`，`!Infinity` 为 false 未被拦住 → 显示"倍率：Infinityx"（浏览器实测发现）
- **修复**：先判 `matchedRatios.length` 为 0 → 显示"倍率：—"。**已部署并复验 PASS**：三卡显示 `1.0x (基准)` / `倍率：—` / `倍率：—`

### ISS-008 输入框偶发奶黄/白底（autofill 污染）

- **现象**：登录页两个输入框偶发奶黄底+黄边框，手动输入时正常——"偶发"即触发条件：Chrome 回填已保存的账号密码（`:-webkit-autofill` 命中）时
- **根因（两层）**：
  1. **SUI form.css 自带 autofill 规则**（产物 CSS 取证）：`.ui.form .field.field input:-webkit-autofill{border-color:#e5dfa1!important;box-shadow:inset 0 0 0 100px ivory!important}`，特异性 (0,4,1)+!important，ivory=#FFFFF0 奶黄——登录页白框真凶；聚焦版高达 (0,6,1)
  2. Chrome UA 对 autofill 输入框强制绘制浅底黑字（SUI 未覆盖的原生 input 也有）
  - 主题层此前零 autofill 处理（全项目 grep 无命中）
- **修复**（[semantic-ui.css:326-361](../../web/default/src/theme/semantic-ui.css)，全局一处覆盖全系统）：
  - 手法：inset 1000px `var(--bg-inset)` 铺主题底色（暗 `#0a0e14`/浅 `#f1f5f9` 自适应）+ `-webkit-text-fill-color` 控字色 + `caret-color` + 9999s 背景色过渡双保险；box-shadow 标准与 -webkit 前缀双写防 Blink 别名级联意外
  - 选择器三档压 SUI：裸元素 `:where(theme) input:-webkit-autofill` (0,1,1) 兜底全系统普通输入框、`html.theme-* .ui.form input:autofill路径` (0,3,1)、`.field.field` 同路径 (0,5,1)；聚焦版 (0,7,1) 压 SUI (0,6,1) 并保留主题聚焦光环
- **验证**：构建产物含两档高特异性规则（正则校验 PASS）；部署后浏览器遍历 styleSheets 确认规则存在且 box-shadow 含 `var(--bg-inset)`（PASS）。真实 autofill 视觉效果需用户浏览器回填账号密码确认（自动化无法触发真实 autofill）
- **排查手法**：怀疑 autofill 污染时，直接在构建产物 CSS 里 grep `autofill`，SUI 真凶规则会直接现形
